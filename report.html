容错测试结果
通过故障注入验证系统降级与自愈能力

测试一：Redis 故障注入

阶段系统状态具体行为
正常三级缓存全链路L1本地缓存 → L2 Redis → L3 MySQL 逐级回源
故障Redis容器停止自动跳过L2，直接查询MySQL；Token验证回退至MySQL校验模式
结果Feed流正常返回接口返回数据正常，延迟有所上升，核心业务不中断
恢复Redis容器重新启动后续请求自动回填热点Key，缓存逐渐恢复至正常命中率，无需人工干预

测试二：RabbitMQ 故障注入

阶段系统状态具体行为
正常异步事件驱动API发MQ事件后立即返回，Worker异步消费落库
故障RabbitMQ容器停止API自动切换为同步直写MySQL和Redis；通知推送暂时跳过
结果点赞功能不受影响点赞操作正常执行，对调用方透明
恢复RabbitMQ容器重新启动Worker恢复正常消费，积压消息逐条处理

测试三：MySQL 连接池压力

超过连接池最大连接数的并发请求，GORM连接池管理机制正确排队等待； 超时请求返回错误而非服务崩溃，连接池保护机制生效。

容错前后性能变化对比

Redis 正常 vs 故障（listLatest QPS）

MQ 正常 vs 降级直写（/like 延迟）

Redis故障后QPS下降但接口仍可用；MQ降级后延迟有所增加但点赞功能不受影响。 两类故障恢复后系统均能自动回填/自愈。

测试结论
维度结论评价
功能完整性 五个核心模块、30个测试用例全部通过，覆盖正常流程、异常输入和边界条件 达成
性能达标 核心Feed流接口500并发下P99延迟340ms（设计目标≤500ms）；50并发下QPS达1521 超额达成
缓存命中率 L1命中率78.5%以上，L1+L2累计命中率92.3%（设计目标≥90%）；singleflight有效合并并发L3回源请求 超额达成
容错能力 Redis故障自动降级查MySQL，RabbitMQ故障自动切换同步直写；两类故障核心业务0中断，恢复后自愈 达成
已知瓶颈 登录接口因bcrypt（cost=10）单次约100ms无法缓存加速，高并发下延迟累积；后续可降低bcrypt cost至8（约25ms/次） 可优化

三项设计指标达成情况
P99延迟 ≤ 500ms实际 340ms达成
缓存命中率 ≥ 90%实际 92.3%达成
组件故障业务不中断降级自愈验证通过达成

测试环境：单机 Docker Compose 部署，i7-12700H + 32GB DDR5 + Windows 11
